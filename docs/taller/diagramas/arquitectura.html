ASCENDX AI — Diagrama de capas (Clean Architecture adaptada a cliente-servidor)

Regla de dependencia: Presentación y Datos dependen del Dominio; el Dominio no depende de ninguna otra capa ni de librerías externas.

CAPA DE PRESENTACIÓNapps/mobile · React Native 0.86 + Expo SDK 57 + TypeScript
Pantallas (Screens)Expo Router: Bienvenida, Registro, Inicio de sesión, Inicio (panel), Simulador, Metas, Asistente, Perfil
Componentes de UIButton, Card, ProgressRing, AnimatedAmount, SegmentedControl, animación del logo
Estado de la vista (ViewModel)AuthProvider (sesión), ThemePreference (modo oscuro/claro) con React Context + hooks
usa reglas y formatos del dominio · pide datos a la capa de datos por HTTPS
CAPA DE DOMINIOpackages/finance-core + servicios de la API · sin dependencias de UI ni de base de datos
Entidades y reglas (finance-core)Capacidad de ahorro y prudente (80 %), reparto entre metas, simulador ahorro / crédito / mixto, tasas EA ↔ MV, aviso de usura, posibles duplicados
Casos de uso (servicios de la API)register, login, refresh, updateProfile, updateConsents, compare, deleteAccount
Contratos (interfaces)Mailer, tipos User / AuthSession, esquemas de validación Zod
implementa los contratos y entrega los datos que el dominio necesita
CAPA DE DATOSadaptadores e infraestructura · apps/api (Render) + almacenamiento del teléfono
Cliente HTTPlib/api.ts: JWT de 15 min y renovación automática
SecureStoreToken de renovación cifrado (Android Keystore)
API RESTExpress 5: /auth, /me, /simulator, /health
RepositorioPrisma 7 ORM → PostgreSQL en Neon (18 tablas)
Servicios externosIA y correo (por seleccionar), ML Kit (P2)

Recuadro con borde punteado = componente planificado. Las cifras financieras siempre se calculan en el dominio; la IA solo recibe resultados ya calculados.
